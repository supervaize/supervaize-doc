# Supervaize MCP: connect Claude or ChatGPT

Ask your chat assistant what your agents are doing, unblock them, and launch new work, without leaving the conversation. The Supervaize MCP connector gives Claude and ChatGPT access to one Studio workspace, **with your own roles and nothing more**.

<ChatReplay only="overview" />

- **One URL, no API key.** You paste a workspace URL and sign in. There is no secret to copy or rotate.
- **Your permissions, exactly.** Every call runs as you. A read-only member cannot write; you only see missions you already see in Studio.
- **Revocable in one click.** Disconnect from your profile and the next call fails immediately.

## Install in four steps

Try the flow here first. The buttons work.

<ConnectFlow />

### 1. Copy your workspace URL

In Studio, open the **Help** menu (the **?** at the bottom of the sidebar) and choose **Use Supervaize in Claude / ChatGPT**. Copy the URL shown. It looks like this:

```text
https://app.supervaize.com/mcp/<your-workspace>
```

![Studio page "Use Supervaize in Claude / ChatGPT" showing the workspace URL and a Copy button](/img/mcp/chat-connectors.jpg)

One URL is one workspace. The same URLs are also listed under **Profile → Developer → Chat connectors (MCP)**.

### 2. Add it in your chat app

Add a **custom connector** and paste the URL, with no trailing slash.

- **Claude** (claude.ai and Claude Desktop): [Get started with custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
- **ChatGPT** (developer mode): [MCP in ChatGPT](https://developers.openai.com/api/docs/mcp)

In Claude's **Add custom connector** dialog, use these settings:

| Setting | Value |
| --- | --- |
| URL | `https://app.supervaize.com/mcp/<your-workspace>` |
| Authentication | **Sign in now** |
| OAuth client | **Use Claude's published identity** |
| Client ID / secret | Leave empty |
| Request headers | None |

:::warning Do not pick "Register automatically"
Supervaize does not offer dynamic client registration, so that option fails. Keep **Use Claude's published identity**.
:::

### 3. Approve the connection

Supervaize opens a consent page. Sign in if you are signed out, confirm the workspace, then choose the permissions:

![Supervaize consent page: Connect Claude to Supervaize, with workspace and Read / Write permissions](/img/mcp/consent.jpg)

| Permission | What the assistant can do |
| --- | --- |
| **Read** (always on) | Browse missions, jobs, cases and their steps as you see them in Studio. |
| **Write** (optional) | Create and manage missions and jobs, tag, comment and rate, answer agent questions and invoke agent actions on your behalf. |

Click **Allow**. **Deny** creates nothing.

:::info Runs with your roles
Granting **Write** never gives the assistant more than you have. If you are a read-only member, write calls are refused whatever you tick here.
:::

### 4. Disconnect when you want

After **Allow**, the app is listed under **Profile → Developer → Connected apps**, with the workspace, the granted permissions and the last use. **Disconnect** revokes it immediately; the next call from Claude or ChatGPT fails until you connect again.

## Check that it works

Open a new chat and ask:

> What is running in my Supervaize workspace?

The assistant should call `workspace_info` and `mission_list`, then answer with your workspace name, your role and your missions. Next: [see what you can do with it](./examples).

## For developers: issuer check and tool-list caching

Claude and ChatGPT users need to do nothing here. These two details matter if you write your own MCP client. They apply to the `2026-07-28` revision of the MCP specification. Studio's tests check only that request shape, and older revisions were not checked.

### The `iss` parameter on every redirect

The authorization server metadata, at `/.well-known/oauth-authorization-server/mcp`, sets `authorization_response_iss_parameter_supported` to `true` ([RFC 9207](https://www.rfc-editor.org/rfc/rfc9207)). Every redirect back to your client then carries an `iss` query parameter. Its value is the issuer: the Studio API origin plus `/mcp`, for example `https://app.supervaize.com/mcp`.

`iss` is present on:

- the approval, together with `code`
- the denial, with `error=access_denied`
- the error redirects of `/mcp/authorize`, for example `error=invalid_scope`

Compare `iss` with the `issuer` you discovered and refuse a mismatch. This stops an answer from a different authorization server (a mix-up attack).

In your callback, pass `iss` to your OAuth library unchanged, with `code` and `state`. A client that reads the metadata flag refuses a redirect without `iss`, so do not strip query parameters from the redirect, for example in a proxy.

### Cache hints on the tool list

A `tools/list` result carries `ttlMs: 900000` (15 minutes) and `cacheScope: "public"`. This holds on both servers: `/mcp/<workspace>` and `/mcp/agent/<workspace>`. The tool lists change only when Studio is released, and they are the same for every caller. A client can keep the list and does not need to ask again on each request.

After a Studio release that adds, removes or changes a tool, a client can show the previous list for up to 15 minutes.

**Caching does not weaken the access rules.** Tool results (`tools/call`) carry no cache hint. They depend on you and on your access rights, so they are never cached. Only the list of tool names and schemas is kept, never the data a tool returns.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `invalid_target` while connecting | The URL does not match the workspace URL exactly | Paste the URL as copied from Studio, without a trailing slash |
| Consent page says the request expired | The page stayed open more than 10 minutes | Start the connection again from the chat app |
| Calls fail after working before | The app was disconnected, or unused for 30 days | Reconnect from the chat app |
| "Token was issued for another workspace" | One connection is one workspace | Add a second connector with the other workspace URL |
| A write is refused | You did not grant **Write**, or your Studio role does not allow it | Reconnect with **Write**, or ask a workspace admin |
