# Notifications and Slack

Studio can tell you about events in your jobs and cases. It can send messages to channels such as Slack and email, and it keeps an in-app list.

Three steps set this up.

1. A workspace admin connects Slack.
2. A member who can edit the mission chooses the events for each agent.
3. Each user reads the in-app notifications.

## Connect Slack

A workspace admin opens **Settings**, then **Integrations**. The page shows one card for each service.

| Service | State |
| --- | --- |
| **Slack** | The card has **Connect Slack** until you connect. Then it has **Settings**. |
| **Email** | The card works the same way. |
| **Google Sheets** | The card works the same way. |
| **WhatsApp**, **Teams**, **SMS** and **Zoom** | The card shows **Coming soon**. A **Request feature** link replaces the status. |

A developer can also see an **n8n** card when n8n is enabled for the workspace.

To connect Slack:

1. On the **Slack** card, select **Connect Slack**.
2. Approve the access in Slack.
3. Studio returns to the **Integrations** page.

Open the **Slack** card again, and select **Settings**. The page shows these cards.

| Card | What it shows |
| --- | --- |
| **Slack workspace** | The Slack workspace name, the connection date, the last check, the token expiry and the **Default channel**. |
| **Available channels** | The channels that Studio can reach. |

In **Available channels**, you can do two things.

- Choose a **Default channel** and select **Save default channel**.
- Choose a channel under **Test sending a message**, then select **Send test message**.

**Disconnect Slack** removes the connection.

## Choose events for an agent

Preferences belong to one agent in one mission. Open the mission page. Each agent card has a **Notifications** button.

The **Notification settings** dialog opens. It has three tabs.

| Tab | What you set |
| --- | --- |
| **Notification preferences** | When each event reaches each channel |
| **Interaction capabilities** | What each channel can do |
| **Memory retention** | Which data the agent keeps: **Deliverables**, **Steps**, **Context** and **Dialogs** |

In **Notification preferences**, each row is an event for a job or a case: `start`, `stop`, `pause`, `human_in_the_loop`, `error` or `unknown`. Each column is a channel: `slack`, `teams`, `email` or `web`.

For each cell, choose one timing.

| Timing | Meaning |
| --- | --- |
| **Off** | No message |
| **Real Time** | At once |
| **Hourly** | One message each hour |
| **Daily** | One message each day |
| **Weekly** | One message each week |

Select **Save preferences** to keep your choices. Select **Reset to agent defaults** to remove them.

Read-only members see the values without these buttons.

## Read your notifications

The bell in the header lists your new notifications. Select **My notifications** at the bottom to see all of them.

**My notifications** includes every workspace that you belong to. Use the **Workspace** filter to narrow the list.

| Column | What it shows |
| --- | --- |
| **Workspace** | The workspace of the notification |
| **Event** | What happened |
| **Source** | Who or what caused it, for example an agent |

Select **Mark notifications as read** to clear the unread count.
