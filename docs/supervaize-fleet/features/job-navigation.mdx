# Navigate a job

The job page is where you follow an agent's run. Its **Cases** section shows every case of the job, and you choose how: a **Board**, a **List** or a **Calendar**.

Switch views, card size and sorting here. This is a working miniature.

<CasesViewDemo />

- **Board** answers "what needs me now?": cases move across status columns.
- **List** answers "show me the numbers": one row per case with dates, cost and steps.
- **Calendar** answers "what happened when?": one column per day.

## The job page at a glance

| Area | What you find there |
| --- | --- |
| **Header** | A **← Back to Mission** link, the job's name and status, its tags, then its actions: **Start**, **Stop**, **Job Rating**, **Job comments**, **Edit**, **Clone**, **Delete** and **Tracing** |
| **Cards** | **Information**, **Instructions**, **Job Fields**, **Job Methods**, **Rule activity**, **Job Metadata**, **Job Definition** and **Dialog Transcript** |
| **Cases** | Every case of the job, in the view you choose |

You only see the actions and cards your role allows. Some cards show only for some agents. **Clone** does not show on jobs of Supervaizer v2 agents.

- **Rules:** the **Rules** button is in the header of the **Rule activity** card. It opens the policy rules of the job.
- **Tags:** the tags sit in the title row. **Add tag** opens a searchable list of the workspace tags, with a **Create** row. Each click saves at once. Read-only and auditor roles cannot edit tags.
- **Tokens:** the **Information** card has a **Tokens** row when you can view costs. It reads **Total**, **Voice** and **Text**, and **Unknown** when some tokens are unclassified. It adds **Estimated** or **Mixed sources** when the count is not exact.

### Configure and Operations

Some agents add a setup screen. Their jobs show two tabs, **Configure** and **Operations**. The job opens on **Configure** in these cases:

- The job has not started.
- The job has no case yet.
- You follow a link that asks for **Configure**, such as the **Open** button of a launched plan in the chat.

Otherwise the job opens on **Operations**, where the cases are.

### Testing and production

When the feature is enabled for your workspace, a job of a Supervaizer v2 agent has a mode. A new job starts in testing mode. A badge beside the title reads **Testing** or **Production**.

| Control | What it does |
| --- | --- |
| **Go live** | Asks **Go live?** to confirm. New cases go to the Production lane. Test cases stay in Testing. |
| **Back to testing** | Asks **Back to testing?** to confirm. New cases go to the Testing lane again. |

- **Mission managers** use these controls.
- **A test case** is a case that the agent creates while the job is in testing mode. The mark never changes, also when you switch the mode.
- **The agent** does not see the mode.
- **A job from the chat, or imported from an existing source,** starts in production mode.

On the board, test cases show in a **Testing** swimlane. On a job with a mode, the default lane reads **Production**.

## The three case views

Open the **Display** menu at the top right of the **Cases** section and pick a **View**.

### Board

The default view. Cases are grouped in **swimlanes**, one per kind of case, and each swimlane has five status columns.

| Column | Cases in it |
| --- | --- |
| **Todo** | Not started yet |
| **In Progress** | Starting, running, or being cancelled |
| **Waiting for Input** | Waiting for a human answer |
| **Success** | Completed |
| **Anomaly** | Failed or cancelled |

- **Swimlanes come from the agent.** Setup, Testing, Work (or Production) and Deliverable come first, then any other in alphabetical order. A case with no kind goes to **Work**.
- **Click a swimlane's name to collapse it.** Studio remembers collapsed swimlanes for each job, in your browser, for 180 days.

:::tip[Start with Waiting for Input]
Those cases are blocked until someone answers. Open one and answer the agent's question to let it resume.
:::

#### Board layouts

In the **Display** menu, **Layout** changes how the board shows the cases.

| Layout | What it shows |
| --- | --- |
| **Horizontal** | Swimlanes, with status columns in each (the default) |
| **Vertical** | One column per swimlane, with the cases stacked by status |
| **Deliverables only** | Only the cases that have deliverables |
| **Dialog** | The cases as a thread, oldest first |

### List

A table with one row per case: **Name**, **Status**, **Lane**, a date, **Cost** and **Steps**.

- **The date column follows the sort.** Sort by Start date and the column shows start dates; the same goes for End date and Last update date.
- **Group by swimlane** in the **Display** menu splits the table into one collapsible block per swimlane.

### Calendar

One column per day, from the first day with a case to the last. A day with nothing shows **No cases**; cases with no date are gathered in a last **No date** column.

Choose which date places a case with **Calendar date** in the **Display** menu: **Created date** (the default), **Started date** or **Finished date**.

### Card size

In the Board and Calendar views, **Cards** switches between two sizes.

| Size | What a card shows |
| --- | --- |
| **Compact** (default) | Name and status |
| **Full** | Name, status, reference, number of steps, cost, and the date you sort by |

## Filter and sort

The **Filters** and **Sort** buttons sit next to the **Cases** title and apply to all three views.

| Control | Options |
| --- | --- |
| **Filters** | Search by text, **Status**, **Agent**, **Swimlane**. **Clear all** removes them. |
| **Sort** | **Case name**, **Start date**, **End date**, **Last update date**; ascending or descending. **Reset to default** restores it. |

The default sort is **Last update date**, newest first.

- **The counters follow the filters.** Total, Completed, Waiting and Failed count only the cases that match, and a line under the cases reads _Showing 3 of 8 cases_.
- **A green dot marks a changed menu.** It shows on Filters, Sort or Display when the menu is not on its defaults.

:::info[View settings are not saved]
The view, card size, filters and sort go back to their defaults when you leave the job page. Only collapsed swimlanes are remembered.
:::

## Open a case, or all of them

- **Click a case** in any view to open it and read its steps.
- **View all** next to the **Cases** title opens the full case list of the job, with pagination and export: **Export CSV** lets you choose the columns, **Full export** exports every field.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| "No cases for this job yet." | The agent has not created a case yet | Wait, or check that the job is started |
| "No cases match the current filters." | A filter or the search hides everything | Open **Filters** and click **Clear all** |
| A swimlane shows only its name | It is collapsed | Click its name to expand it |
| No cases on a job with a **Configure** tab | You are on the setup screen | Switch to the **Operations** tab |
| No **Go live** button | The feature is off for your workspace, the agent is not Supervaizer v2, or you are not a mission manager | Ask a workspace admin |
| The view went back to Board | View settings are not saved between visits | Pick the view again in **Display** |
