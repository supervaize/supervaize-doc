# Manage agents

An agent registers itself with Studio. You do not add it by hand. The agent appears in your **Agents** list.

Workspace admins can see the servers that agents register through. Open **Advanced**, then **Servers**. This item shows only when servers are enabled for the workspace.

## The Agents list

Each agent has a card with its status and an onboarding badge.

The onboarding badge reads **New**, **Updated**, **Pending Setup**, **Operational** or **Decommissioned**.

To narrow the list, use **Search agents...** or the **Status** filter. The status values are **Active**, **Inactive**, **Suspended**, **Error**, **Inaccessible** and **Paused**.

## The agent page

The header shows the name, the status and the description.

Agent managers see two tabs.

| Tab | What it shows |
| --- | --- |
| **Overview** | The details of the agent, described below |
| **Activity** | The jobs and cases of the agent per status, with **Jobs per day** and **Cases per day** charts |

Other members see the overview only.

| Card | What it shows |
| --- | --- |
| **About** | The full description that the agent sends when it registers. |
| **Agent Info** | **Slug**, **Name**, **Runtime**, **Version**, **Supervaizer SDK**, **Author**, **Developer**, **Maintainer**, **Editor**, **Environment**, **Server**, **Onboarding**, **Tags**, **Created** and **Updated**. A row shows only when the agent gives a value. |
| **Parameters** | The settings of the agent. |
| **Rating** | The ratings of the agent. See [Ratings](./rating-analytics). |

### Set parameters

The agent declares its own parameters. Each parameter shows its name and a **Set** or **Not Set** badge. A key icon marks a secret.

1. Type a value in the field. A secret field hides the value.
2. Repeat for each parameter to change.
3. Select **Save Parameters**.

Studio saves only the values that you touched.

The controller reads the values when it starts. After you change a value, the developer restarts the controller. See [Parameters](/docs/supervaizer-controller/parameters).

## Header actions

| Button | What it does |
| --- | --- |
| **New Mission** | Creates a mission for this agent. See [Create a mission](./mission-management). |
| **Pause** or **Resume** | Pauses the agent or ends the pause. |
| **Edit** | Edits the agent. |
| **LLM settings** | Opens the settings of an LLM agent. |
| **Delete** | Deletes the agent. |
| **Request Publication** or **Unpublish** | Asks to publish the agent, or withdraws it. |
| **Remove from workspace** | Removes a shared agent from your workspace. |

Edit, delete and publication actions belong to the workspace that owns the agent.

## Pause an agent

The owner of an agent can pause it.

1. Select **Pause**.
2. In the **Pause agent** dialog, read the warning.
3. Confirm.

If jobs run, the dialog lists them. Select **Pause anyway and stop N jobs** to continue, or **Cancel**.

A paused agent behaves as follows.

- Studio stops its health checks.
- Studio blocks all operations of the agent. The job **Start** button is disabled, and its tooltip reads **Agent paused**.
- The status is **Paused**.
- A banner shows the date and the reason.

Only the owner can end the pause. Select **Resume**.

A server that stays down for a long time is paused with its agents. The default delay is 24 hours.

Pause exists in Studio only. It sends nothing to the agent server.

## Share an agent

You can share an agent with another workspace. The **Workspace Access** card on the shared agent shows the state of the authorization.

The receiving workspace must accept the agent before any job can start. A workspace admin or an agent manager of that workspace accepts it and sets the agent workspace reference.
