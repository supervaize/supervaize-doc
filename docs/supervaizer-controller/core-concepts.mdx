# Missions, jobs, cases and steps

Supervaize Studio shows the work of every agent with the same four levels. Your first task, before any code, is to decide what each level means for your agent.

| Level | What it is | Who owns it | Example: an interview agent |
| --- | --- | --- | --- |
| **Mission** | A business goal. It groups agents, people, rules and jobs. | Studio | "Customer research 2026" |
| **Job** | One unit of work that an operator starts and follows. | Studio keeps the record; the agent owns the business state | One interview campaign |
| **Case** | One business item inside a job. | Agent | One interview with one contact |
| **Step** | One observable activity inside a case. | Agent | Invite, interview, summarize |

A mission can hold many jobs. A job holds one or more cases. A case holds one or more steps.

![A mission page in Studio with its agent and its jobs](/img/controller/mission-page.png)

## How the levels show in Studio

The job page lists the cases of the job, with their status and cost.

![The cases of a job in Studio, with their status and cost](/img/controller/job-cases.png)

A case page lists its steps. Each step shows its status, its cost and what it produced.

![A case with two steps and a deliverable](/img/controller/case-steps.png)

## Choose your mapping

Answer these questions for your agent. The [integration skill](/docs/integrations/skills/supervaizer-integration) asks them one round at a time and challenges vague answers.

**Mission**

- Which business goal do several runs of your agent serve together?
- What must be shared by all jobs of a mission: people, rules, contacts, context?

**Job**

- What does an operator start with one click? What is finished when the job is finished?
- Can the same job run again, or does each run need a new job?
- Does the job need setup after it is created and before it works?

**Case**

- What is the item that an operator wants to see on one line, with one status? A contact, a document, a ticket, a lead?
- Is the number of cases known at the start, or do cases appear while the job runs?
- If one case fails, do the others continue?

**Step**

- Which activities of a case does an operator need to see?
- Which step costs money? Which step produces something to open or export?
- Which step must wait for a person? Which step has an effect that a mission rule must be able to stop?

:::tip[Rules of thumb]

- If operators ask "how many are done?", the thing they count is the **case**.
- A step is worth showing when it can fail, wait, cost money or produce an output. Do not show internal function calls.
- One case with five clear steps is better than five cases with one step.

:::

## How your agent reports them

Your agent does not call Studio for each change. It returns a **job state** from its actions, and Studio shows it. This is a complete job state with one case and two steps:

```json
{
  "job": {
    "id": "01M3KEF6A9M0FS50Q5YP0TPG1Y",
    "agent_slug": "hello-world-ai-agent",
    "mission_id": "01KSXM5HRAEPDADSKM625KJS6V",
    "status": "completed",
    "source": { "type": "fresh_start" },
    "information": { "cost": { "total_cost": 0.2 } }
  },
  "cases": [
    {
      "id": "job-1-case-1",
      "lane": "work",
      "title": "Hello Ada (1)",
      "status": "completed",
      "metadata": { "name": "Ada", "city": "Paris" },
      "steps": [
        { "id": "job-1-case-1-start", "activity": "operation", "status": "completed", "title": "Start", "cost": 0.1 },
        {
          "id": "job-1-case-1-say-hello",
          "activity": "operation",
          "status": "completed",
          "title": "Deliver greeting card",
          "cost": 0.1,
          "outputs": [{ "id": "job-1-case-1-card", "type": "greeting_card", "title": "Hello, Ada from Paris!" }]
        }
      ]
    }
  ]
}
```

- **Statuses** are `pending`, `active`, `awaiting`, `completed`, `failed` and `cancelled`. A failure is a status, not a kind of step.
- **`lane`** groups cases on the job page. The default lane is `work`. Agents often add `setup` and `deliverable`.
- **`activity`** of a step is `operation` or `delegation`.
- **`awaiting`** on a step means that it waits for a person. See [Human in the loop](human-in-the-loop).
- **`cost`** and **`outputs`** are explained in [Cost reporting](cost-reporting).

### Declare lanes and output types

Declare your lanes and output types in the registration:

```python
build_v2_agent_registration(
    ...,
    case_lanes=[{"id": "work", "label": "Work", "default": True}, {"id": "deliverable", "label": "Deliverables"}],
    artifact_types=[{"type": "greeting_card", "label": "Greeting card"}],
)
```

Studio loads the content of an output with the `artifact.get` action. Declare `artifact.get` with `mutating=False`. A job can also start from external work: set `job.source` to `{"type": "external"}` in place of `fresh_start`.

### Mission context

Studio can send the mission with each request. `request.mission` holds the mission `id`, `name` and `metadata`. The SDK does not read the metadata keys. Your agent owns their meaning. Do not copy the metadata into the job. See the [SDK guide](ref/2026_05_SUPERVAIZER_v2.md).

## How Studio talks to your agent

Studio uses two kinds of calls:

- A **surface** is a screen that your agent describes and Studio draws: a start form, a review form, a Configure screen, a dashboard.
- An **action** is a command that Studio invokes: start the job, sync the job, submit an answer, save a setting.

Your agent declares its surfaces and actions once, in its registration. [Build your controller](controller-setup) shows how.
