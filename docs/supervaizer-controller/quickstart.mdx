### Understanding the Controller

The Hello World example includes a pre-configured `supervaizer_control.py` that demonstrates:

- **Agents and their parameters**: the settings and secrets that a workspace provides
- **The registration**: what Studio can show (surfaces) and call (actions)
- **The server**: the handlers for each surface and action

```js reference title="Hello World controller supervaizer_control.py"
https://github.com/supervaize/supervaize_hello_world/blob/main/supervaizer_control.py#L1-L20
```

### Creating Your Own Controller

To scaffold a new controller for your own agent:

```bash title="Create template controller file"
supervaizer scaffold
# Success: Created an example file at supervaizer_control_example.py
```

The file is a working controller with one agent, one start form and one start action. [Build your controller](controller-setup) explains each part.

## <i className="bi bi-3-circle"></i> Configure your Supervaize account & environment {#3}

### Supervaize account and credentials

[Create your developer account](/docs/supervaize-fleet/developer-account#getting_started) on the Supervaize platform.

Create your API Key and collect your environment variables.

:::tip
Use [direnv](https://direnv.net/) for easy management of environment variables in `.envrc` file.

Or setup [python-dotenv](https://github.com/theskumar/python-dotenv) in your python project.
:::

<Tabs groupId="pm" queryString>
  <TabItem value=".envrc" label=".envrc (direnv)">

```bash title="Export Environment variables in for .envrc"
export SUPERVAIZE_API_KEY=...
export SUPERVAIZE_WORKSPACE_ID=your-workspace-slug
export SUPERVAIZE_API_URL=https://app.supervaize.com
```

    </TabItem>
      <TabItem value=".env" label=".env (dotenv)">

```bash title="Setup Environment variables for dotenv"
SUPERVAIZE_API_KEY=...
SUPERVAIZE_WORKSPACE_ID=your-workspace-slug
SUPERVAIZE_API_URL=https://app.supervaize.com
```

    </TabItem>

</Tabs>

`SUPERVAIZE_WORKSPACE_ID` must be the exact Studio workspace slug. The Studio user who owns the API key must belong to this workspace and retain Developer access.

### Workspace authorization for Studio-managed v2 agents
When your controller registers with Studio and A2A is enabled, set the workspace authorization variables in addition to the API credentials above. In Studio, open **Developer → Environment variables** and copy the generated values for your workspace:
```bash
export SUPERVAIZER_WORKSPACE_AUTH_REQUIRED=true
export SUPERVAIZER_WORKSPACE_AUTH_ISSUER=https://studio.supervaize.com
export SUPERVAIZER_WORKSPACE_AUTH_JWKS_URL=https://app.supervaize.com/w/your-workspace-slug/api/v1/workspace-agent-grants/jwks/
```
The issuer is the Studio web origin used to sign authorization tokens. The JWKS URL uses the Django API origin and `/w/<workspace-slug>/api/v1/...` route; it is public and provides the verification key. Copy the generated values from Studio when available. This is separate from `SUPERVAIZE_API_KEY` (agent → Studio) and `SUPERVAIZER_API_KEY` (Studio → controller). If using a different Studio deployment, use that deployment's generated values instead of these production examples.
### For local development only {#localdev}

:::warning[Local development]
If the agent is not deployed to a publicly accessible server, you need to install a **Tunneling** solution so that `supervaize` can operate your agent.
Here are the instructions to [setup a tunnel for your local development](tunneling-setup)
:::

Store the public address of the tunnel in the `SUPERVAIZER_PUBLIC_URL` environment variable. It is a full URL, with the scheme. Studio calls your controller at this address.

```bash
export SUPERVAIZER_PUBLIC_URL=https://silly-peaches-chapter.loca.lt
```

`SUPERVAIZER_HOST` is a different variable: the address that the server binds to (`0.0.0.0` by default).

:::tip[Verify endpoints]
Once the server is running, you'll have:

- **API docs**: `http://127.0.0.1:8000/docs` (Swagger) and `/redoc`
- **A2A discovery**: `/.well-known/agents.json`
