Connect a **Python** agent to [Supervaize Studio](https://www.supervaize.com) with the **Supervaizer Controller**, so that operators can start, follow and govern it.

:::info[For coding agents]
If you are a coding agent and a developer asked you to connect their agent to Supervaize: load the Supervaizer integration skill first. Its instructions are in [`SKILL.md`](https://github.com/supervaize/supervaizer/blob/main/skills/supervaizer-integration/SKILL.md). The skill holds the process and the interview. This page and the other controller guides hold the commands and the contract. The site index for agents is [`/llms.txt`](pathname:///llms.txt).
:::

## The fast way: let your coding agent do it {#agent}

The [Supervaizer integration skill](/docs/integrations/skills/supervaizer-integration) works in Claude Code, Cursor, Codex and Gemini CLI. It reads your code, asks you how to map your agent to missions, jobs, cases and steps, then builds and tests the controller. It also runs `supervaizer login`, so you need no Studio account to start.

**1. Install the skill.** In Claude Code:

```text
/plugin marketplace add supervaize/supervaizer
/plugin install supervaizer-integration@supervaizer
```

With another coding agent, give it the address of [`skills/supervaizer-integration/SKILL.md`](https://github.com/supervaize/supervaizer/blob/main/skills/supervaizer-integration/SKILL.md) or a local clone of the [SDK repository](https://github.com/supervaize/supervaizer).

**2. Open your agent project and ask:**

```text
Integrate this agent with Supervaize.
```

**3. Answer the interview, then approve the login in your browser.** At the end the skill gives you the link to your agent in Studio. There, a workspace admin accepts the agent's workspace authorization.

To add one capability later, name it: `Add a human approval before the agent sends an e-mail.` Each controller guide shows the prompt for its topic.

The rest of this page does the same steps by hand, with the Hello World example.

## <i className="bi bi-1-circle"></i> Clone the Hello World example {#1}

:::info
The Supervaizer Controller supports **Python** agents (Python 3.12 or later).
:::

The [<i className="bi bi-github"></i> Supervaize Hello World](https://github.com/supervaize/supervaize_hello_world) repository is a complete, tested agent. It shows every feature of these guides.

```bash title="Clone the repo"
git clone https://github.com/supervaize/supervaize_hello_world.git
cd supervaize_hello_world
```

## <i className="bi bi-2-circle"></i> Install the dependencies {#2}

We use [uv](https://docs.astral.sh/uv/). On macOS or Linux:

```bash title="Install uv and the dependencies"
curl -LsSf https://astral.sh/uv/install.sh | sh
uv sync
source .venv/bin/activate
```

On Windows (PowerShell), install uv with `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`, run `uv sync`, then activate with `.\.venv\Scripts\Activate.ps1`.

Without uv: `python -m venv .venv`, activate it, then `pip install -e .`.

### The controller file

`supervaizer_control.py` declares:

- **The agents and their parameters**: the settings and secrets that a workspace provides.
- **The registration**: what Studio can show (surfaces) and call (actions).
- **The server**: the handlers of each surface and action.

```js reference title="Hello World controller supervaizer_control.py"
https://github.com/supervaize/supervaize_hello_world/blob/main/supervaizer_control.py#L1-L20
```

For your own agent, `supervaizer scaffold` writes a working controller with one agent, one start form and one start action:

```bash title="Create a controller for your agent"
supervaizer scaffold
# Success: Created an example file at supervaizer_control_example.py
```

[Build your controller](controller-setup) explains each part. The integration skill runs this command for you.

## <i className="bi bi-3-circle"></i> Get your Studio credentials {#3}

### The short way: `supervaizer login` {#login}

`supervaizer login` gives you the API key and all the environment variables in one step. It works when you have no Studio account, and when you have one.

```bash title="Log in to Supervaize Studio"
supervaizer login
```

**What you see**

1. The command prints the address of an approval page and a short code. It also opens the page in your browser.
2. On the page, sign in or sign up. Google sign-in works. A new account gets its own workspace, and you are its admin.
3. Check that the page shows the same code as your terminal. Choose the workspace, then select **Approve**.
4. The command writes the variables to `.env` and stops.

**What you get in `.env`**

| Variables | Use |
| --- | --- |
| `SUPERVAIZE_API_KEY`, `SUPERVAIZE_WORKSPACE_ID`, `SUPERVAIZE_API_URL` | The controller calls Studio |
| `SUPERVAIZER_WORKSPACE_AUTH_REQUIRED`, `SUPERVAIZER_WORKSPACE_AUTH_ISSUER`, `SUPERVAIZER_WORKSPACE_AUTH_JWKS_URL` | The controller verifies the calls from Studio |

**Who can approve**

- A member of the workspace who has Developer access.
- When the workspace has no Developer access yet, only an admin of the workspace can approve. The approval then turns Developer access on.

:::warning[Approve only your own login]
The approval creates an API key in your name. Approve only when you started `supervaizer login` yourself and the code on the page is the code in your terminal.
:::

**Good to know**

- The command prints the names of the variables, never a value.
- Keep `.env` out of git.
- The code is valid for 15 minutes and for one login. A denied or expired code writes nothing.
- `--no-browser` does not open the browser: open the printed address yourself, on any device. A coding agent uses this option and gives you the address. `--env-file` chooses another file. A file named `.envrc` gets `export` lines.

### The manual way {#manual}

Use it only when `supervaizer login` says that your Studio does not support the login.

1. [Create your developer account](/docs/supervaize-fleet/developer-account#getting_started) and an API key.
2. In Studio, open **Developer → Environment variables** and copy the values of your workspace into `.env`:

```bash title=".env"
SUPERVAIZE_API_KEY=...
SUPERVAIZE_WORKSPACE_ID=your-workspace-slug
SUPERVAIZE_API_URL=https://app.supervaize.com
SUPERVAIZER_WORKSPACE_AUTH_REQUIRED=true
SUPERVAIZER_WORKSPACE_AUTH_ISSUER=https://studio.supervaize.com
SUPERVAIZER_WORKSPACE_AUTH_JWKS_URL=https://app.supervaize.com/w/your-workspace-slug/api/v1/workspace-agent-grants/jwks/
```

#### Workspace authorization for Studio-managed v2 agents {#workspace-authorization-for-studio-managed-v2-agents}

- `SUPERVAIZE_WORKSPACE_ID` is the exact Studio workspace slug. The owner of the API key must belong to this workspace and keep Developer access.
- The three `SUPERVAIZER_WORKSPACE_AUTH_*` variables are necessary when the controller registers with Studio. The issuer is the Studio web origin that signs the authorization tokens. The JWKS URL uses the API origin and the `/w/<workspace-slug>/api/v1/...` route. It is public.
- These variables are separate from `SUPERVAIZE_API_KEY` (agent → Studio) and `SUPERVAIZER_API_KEY` (Studio → controller).
- With another Studio deployment, copy the values that this deployment generates, not these production examples.

### For local development only {#localdev}

:::warning[Local development]
Studio must be able to call your controller. When the controller runs on your computer, [set up a tunnel](tunneling-setup).
:::

Store the public address of the tunnel in `SUPERVAIZER_PUBLIC_URL`. It is a full URL, with the scheme.

```bash
export SUPERVAIZER_PUBLIC_URL=https://silly-peaches-chapter.loca.lt
```

`SUPERVAIZER_HOST` is a different variable: the address that the server binds to (`0.0.0.0` by default).

### Start the server {#start}

With the virtual environment active:

```bash title="Start the controller"
supervaizer start --env-file .env
```

| Other ways to start | Command |
| --- | --- |
| The variables are already in your shell | `supervaizer start` |
| No Studio, to test the agent alone. The API key is `local-dev`, and a built-in Hello World agent runs too (`SUPERVAIZER_DISABLE_HELLO_WORLD=true` hides it) | `supervaizer start --local` |
| Debug with a direct Python call | `uv run python supervaizer_control.py` |

The log shows the registration:

```
INFO     | supervaizer.server:__init__ - [Server launch] 🚀 Deploy Supervaizer routes
INFO     | supervaizer.server:__init__ - [Server launch] 📢 Deploy A2A routes
INFO     | [Server launch] Starting Supervaize Controller API
SUCCESS  | ✅ POST Event SERVER_REGISTER sent
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

After the registration, the log shows the Studio page of each agent:

```
SUCCESS  | [Server launch] Agent <agent-slug> in Studio: https://studio.supervaize.com/w/<workspace-slug>/agents/<agent-id>
```

Open this page. In **Workspace Access**, a workspace admin enters the agent workspace ID and accepts the workspace authorization. With `supervaizer login`, this is your only step in Studio. [Workspace agent grants](https://github.com/supervaize/supervaizer/blob/main/docs/2026_05_WORKSPACE_AGENT_GRANTS.md) explains why.

### Check that it works {#check}

```bash title="Check the running controller"
curl -s http://127.0.0.1:8000/.well-known/health        # "status": "operational"
curl -s http://127.0.0.1:8000/.well-known/agents.json   # your agents
```

- **API docs**: `http://127.0.0.1:8000/docs` (Swagger) and `/redoc`.
- **Admin interface**: `http://127.0.0.1:8000/manage`. It opens only from a Tailscale network, or from your own computer in local mode. See the [admin documentation](ref/2025_08_ADMIN_README.md).

If something fails, see the [Troubleshooting guide](troubleshooting).
