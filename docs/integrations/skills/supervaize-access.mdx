# Supervaize Access

**Repository**: [<i className="bi bi-github"></i> runwaize_skills/supervaize_access](https://github.com/runwaize/runwaize_skills/tree/main/supervaize_access)

This skill is for **Supervaize users** (customers). It tells your AI assistant (Claude, ChatGPT, Cursor, Codex) how to operate your Supervaize workspace. The assistant uses the Supervaize MCP connector for missions, jobs, cases and human answers. A helper reads agents and controller events with your API key.

:::info[When to use]
Use this skill when you want a chatbot or an IDE agent to **operate an existing Supervaize workspace**.
:::

This is a **separate skill** from [Supervaizer Integration](/docs/integrations/skills/supervaizer-integration), which connects a custom Python agent to Supervaize Studio.

---

## Overview

| Surface | URL | Capabilities |
| --- | --- | --- |
| **MCP connector (user tools)** | `{base_url}/mcp/{team_slug}` | Missions, jobs, cases, steps, human answers and schedules, as the signed-in user. Auth: OAuth sign-in. See [Connect Claude or ChatGPT](/docs/supervaize-fleet/mcp-connector/install). |
| **REST API** | `{base_url}/w/{team_slug}/api/v1/` | Read **agents** and **controller events** with `Api-Key: <key>`. See [REST API](#rest-api-agents). |
| **MCP server (agent runtime)** | `{base_url}/mcp/agent/{team_slug}` | Case and step reporting for a workflow, for example n8n. Auth: Bearer token of a workspace runtime grant. This skill does not use it. |

**Permissions**: Calls run with your workspace roles. A member with a read-only role can read, and a write operation returns a permission error.

**Limits of an API key**: An API key does not create a mission, start a job, or read a case. It does not open an MCP endpoint. Use the MCP connector for those.

---

## Getting an API key

1. Log in to Supervaize Studio.
2. Open your profile menu and select **Developer**. The page needs Developer access (Workspace Manager or Developer role).
3. Click **Create API Key** and copy the key value (shown once). **Revoke API key** removes a key.
4. The key is scoped to your user; you can only access workspaces (teams) you are a member of.

## REST API (agents) {#rest-api-agents}

- **Base URL**: `https://<your-studio>/w/<team_slug>/api/v1/`
- **Authentication**: `Authorization: Api-Key <your-key>`.

**Agents** (read only): `GET .../agents/` (list), `GET .../agents/{id}/`, `GET .../agents/by-slug/{slug}/`.

**Controller events** (read): `GET .../ctrl-events/` (list), `GET .../ctrl-events/{id}/`. Add the header `workspace: <team_slug>`.

The mission, job and case endpoints need a signed-in Studio session. An API key does not open them.

For request/response fields, see the OpenAPI schema at `{base_url}/api/doc` or `{base_url}/api/doc/swagger-ui/`.

## MCP server

Studio has two MCP endpoints. Both are workspace-bound. Neither is under `/api/`.

| Endpoint | For | Authentication |
| --- | --- | --- |
| `https://<your-studio>/mcp/<team_slug>` | A chat assistant or IDE agent that works as you. | OAuth sign-in and consent. Calls run with your workspace roles. |
| `https://<your-studio>/mcp/agent/<team_slug>` | A workflow runtime, for example n8n. | Bearer token of a runtime grant for the workspace. |

The user endpoint needs the MCP connector to be enabled for the workspace. Steps, consent and tool list: [Connect Claude or ChatGPT](/docs/supervaize-fleet/mcp-connector/install).

An API key does not authenticate on either MCP endpoint.

### Agent runtime tools

| Tool                        | Purpose                                                   |
| --------------------------- | --------------------------------------------------------- |
| `report_case_start`         | Create a case for a job (`job_id`, `execution_id`)        |
| `report_case_step`          | Create or update a case step                              |
| `request_human_input`       | Create a human-in-the-loop step (case set to awaiting)    |
| `get_case_status`           | Get case status by `execution_id`                         |
| `report_case_status`        | Update case status (e.g. completed, failed)               |
| `register_agent_parameters` | Register n8n workflow parameters for an agent             |

The [n8n Integration](/docs/integrations/n8n-integration) page shows how a workflow uses them.

## What the skill does

The skill maps your request to a tool of the MCP connector, or to a command of its helper.

| You say | With the MCP connector | With the helper (API key) |
| --- | --- | --- |
| "Register to Supervaize" | Not applicable | `register-to-supervaize` |
| "List the agents" | `agent_list` | `list-agents` |
| "Show the missions" | `mission_list`, `mission_get` | Not possible |
| "Create a mission" | `mission_create` | Not possible |
| "Start a job" | `job_setup` | Not possible |
| "View the cases and the steps" | `case_list`, `case_get` | `view-cases-steps` (best effort) |
| "Answer the agent" | `step_submit` | Not possible |
| "Status of the jobs for this agent" | `job_list`, `job_get` | `job-status-for-agent` (best effort) |

When a request is not possible and the connector is not connected, the assistant tells you to connect it.

## Helper setup

The helper is optional. Use it when the MCP connector is not connected.

```bash
export SUPERVAIZE_API_KEY=...
export SUPERVAIZE_WORKSPACE_ID=your-workspace-slug
export SUPERVAIZE_API_URL=https://app.supervaize.com

pip install typer
python scripts/supervaize_access_helper.py register-to-supervaize --pretty
```

`register-to-supervaize` reads one page of agents. This proves the key, the URL and the workspace slug together. It saves a local profile for the next commands. It creates nothing in Supervaize.

## Helper commands

| Command | What it does |
| --- | --- |
| `questions` | Prints the questions that the assistant asks first |
| `env-status` | Shows which settings are present |
| `register-to-supervaize` | Validates the key and the workspace, and saves the profile |
| `list-agents` | Lists the agents of the workspace |
| `view-cases-steps` | Rebuilds cases and steps from the controller events. Filter with `--job-id` or `--case-id` |
| `job-status-for-agent` | Summarizes the job events of one agent (`--agent-slug`) |

```bash
python scripts/supervaize_access_helper.py view-cases-steps --job-id 01H... --pretty
python scripts/supervaize_access_helper.py job-status-for-agent --agent-slug my-agent --pretty
```

The last two commands are a best effort. The result depends on the identifiers that the agent puts in its events. The connector tools `case_list` and `job_list` are exact.
